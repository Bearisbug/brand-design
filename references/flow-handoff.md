# 开发视觉交接流程

适用于把现有品牌视觉规则变成约定平台的配置和消费示例。执行依据为 [BD-HANDOFF-001](handoff.md#bd-handoff-001)；阶段进入点见 [阶段导航](flow-stages.md)。

| 步骤 | 实际行动 | 继续条件与产物 |
| --- | --- | --- |
| 1. 定位平台与现有输入 | 读取简报、选稿、品牌参数和已有工程约束，界定语言/模式/组件/状态及独立示例或产品接入 | 继承已知答案；只问阻碍当前交付的缺项。已有品牌规则可直接进入，不重做Logo探索。 |
| 2. 确定权威参数与绑定 | 对照品牌角色，记录实际需要的UI语义、单位、引用与目标属性；补齐本次确需的正式资产源 | 每个目标值能追到输入或有依据的新决定；规范、示例与导出没有相互冲突的维护源。 |
| 3. 生成可消费配置 | 制作本平台tokens导出、字体/fallback和资产映射；保留实际使用说明及依赖 | 文件真实存在，引用可解析；格式名称/版本与实际内容一致。只完成数据检查不能计作平台通过。 |
| 4. 接入最小样例 | 在本次约定环境实际引用配置，制作组件与状态；已有产品接入按授权范围实施 | 样例直接消费交付文件；状态有实际触发方式，模拟范围明确。 |
| 5. 验证、修正与交付 | 按该卡及 [BD-QA-001](assets.md#bd-qa-001)检查真实绑定、字体/资产、版面和状态 | 分别记录数据、配置生成、平台消费和目检结果；修正当前缺陷，交付入口与限制。 |

仅需静态交接说明时，执行对应步骤并保留未运行的接入状态。需要Web时可读 [Web消费验证](handoff-web.md)；其他平台依据实际目标工具核验，不承诺未使用的平台。
