# Web 视觉交接的消费验证

仅在 [BD-HANDOFF-001](handoff.md#bd-handoff-001) 的目标为Web时读取。本页是验证操作提示，不要求采用特定框架、token工具或文件命名。

1. 从交付说明启动实际样例，确认CSS、字体和图片由当前包加载。存在真实产品工程时使用其既定构建与运行方式；独立示例的通过范围限于该示例。
2. 在使用位置检查计算样式，例如实际文字/背景颜色、字号/字重、行高、间距与边框。CSS自定义属性存在不等于其值被目标属性接受；同时核对源数据、映射和最终属性，检查本次用到的每种模式。
3. 确认匹配的FontFace及文件请求，用品牌名、实际标题/正文/状态和本次语言检查渲染。`document.fonts.ready`与`document.fonts.check()`不能单独证明目标字体生效；结合真实字体资源、匹配描述符、已知字形覆盖和实际文字查看。fallback作为降级使用时单独记录，不把降级结果算成品牌字体通过。
4. 对承诺组件实际触发悬停、按下、键盘焦点、禁用、错误或反馈状态。只展示一排手写状态标签不能证明真实交互状态采用同一配置。检查状态信息是否还有文字或其他可见线索；按使用范围验证对比、焦点可见、标签与错误关联。
5. 在约定的桌面/窄屏及实际语言下查看文字完整性、资源比例与状态布局。复制一份交付材料到新的本地目录，按照其说明加载或重建可帮助发现开发机绝对路径依赖；只在声称可迁移交付时承担这一验证。
6. 按 [BD-QA-001](assets.md#bd-qa-001)保存当前输入、导出、样例与证据的对应关系。只要自动重建沿用QA状态，就执行该卡的失效验证；未改资产与运行环境且证据仍对应时，不重复生成无关设计。

使用交换格式或转换工具时，查询其当前官方格式与实际支持；DTCG Format、Resolver和具体转换器分别核对。本页不能代替工具自身的格式验证或完整Web可访问性审计。
